## 1. 项目概述

### 1.1 项目背景
随着数字化生活的发展，情侣之间需要一个私密、安全、美观的平台来记录和分享彼此的美好回忆。传统的社交媒体平台缺乏私密性和个性化，而现有的博客系统又不够贴合情侣使用的场景。

### 1.2 项目目标
- **主要目标**: 构建一个专为情侣设计的私密博客平台，支持记录文字、图片、时间轴等多种形式的内容
- **技术目标**: 采用前后端分离架构，模块化设计，便于后续扩展为微服务架构
- **商业目标**: 为未来商业化（如会员服务、增值功能）打下基础

### 1.3 目标用户
- **主要用户**: 情侣用户（两人共同使用一个账号）
- **用户特征**: 
  - 年龄：18-35岁
  - 需求：记录日常、保存回忆、情感表达
  - 技术水平：中等，能使用常见应用

## 2. 功能需求

### 2.1 用户认证模块 (MVP)

#### 2.1.1 用户注册
- **功能描述**: 新用户可以通过邮箱或用户名注册账号
- **输入要求**:
  - 用户名：3-50个字符，仅支持字母、数字、下划线
  - 邮箱：标准邮箱格式验证
  - 密码：至少8位，包含字母和数字
  - 昵称：可选，默认使用用户名
- **业务规则**:
  - 用户名和邮箱必须唯一
  - 密码需加密存储
  - 注册成功后自动登录
- **异常处理**:
  - 用户名已存在 → 提示"用户名已被使用"
  - 邮箱已存在 → 提示"邮箱已被注册"
  - 密码强度不足 → 提示密码要求

#### 2.1.2 用户登录
- **功能描述**: 用户通过用户名/邮箱和密码登录
- **输入要求**:
  - 用户名/邮箱
  - 密码
- **业务规则**:
  - 支持用户名或邮箱登录
  - 登录成功后返回 JWT Token
  - Token 有效期：30分钟
  - 支持"记住我"功能（延长 Token 有效期）
- **异常处理**:
  - 用户名不存在 → 提示"用户名或密码错误"（不暴露具体信息）
  - 密码错误 → 提示"用户名或密码错误"
  - 账号被禁用 → 提示"账号已被禁用，请联系管理员"

#### 2.1.3 用户登出
- **功能描述**: 用户主动退出登录
- **业务规则**:
  - 清除本地 Token
  - 将 Token 加入黑名单（Redis）
  - 跳转到登录页

#### 2.1.4 用户信息管理
- **功能描述**: 查看和修改个人资料
- **功能点**:
  - 查看个人信息（用户名、邮箱、昵称、头像、注册时间）
  - 修改昵称
  - 上传/修改头像
  - 修改密码（需验证旧密码）

---

### 2.2 博客内容模块 (MVP)

#### 2.2.1 创建博客
- **功能描述**: 用户创建新的博客文章
- **输入要求**:
  - 标题：必填，1-200个字符
  - 内容：必填，支持 Markdown 格式，最大 10000 字符
  - 标签：可选，多个标签，每个标签 1-20 个字符
  - 是否公开：布尔值（默认私有）
  - 发布时间：可选，支持定时发布（未来功能）
- **业务规则**:
  - 博客内容存储在 MongoDB
  - 自动记录创建时间和更新时间
  - 自动关联作者信息
- **异常处理**:
  - 标题为空 → 提示"标题不能为空"
  - 内容为空 → 提示"内容不能为空"
  - 标题过长 → 提示"标题不能超过200个字符"

#### 2.2.2 博客列表
- **功能描述**: 查看用户的所有博客文章
- **功能点**:
  - 分页显示（默认每页10条）
  - 按时间倒序排列（最新在前）
  - 支持按标签筛选
  - 支持搜索（标题、内容）
  - 显示标题、摘要、创建时间、标签
- **业务规则**:
  - 仅显示当前用户的博客
  - 支持分页查询
  - 支持缓存（Redis）

#### 2.2.3 博客详情
- **功能描述**: 查看单篇博客的完整内容
- **功能点**:
  - 显示完整标题、内容、标签
  - 显示创建时间、更新时间
  - 支持编辑、删除操作
  - 支持 Markdown 渲染

#### 2.2.4 编辑博客
- **功能描述**: 修改已存在的博客文章
- **业务规则**:
  - 仅作者可以编辑
  - 更新"更新时间"字段
  - 保留编辑历史（未来功能）

#### 2.2.5 删除博客
- **功能描述**: 删除博客文章
- **业务规则**:
  - 仅作者可以删除
  - 软删除（标记删除，保留数据，未来功能）
  - 当前版本：硬删除

## 3. 非功能需求

### 3.1 性能需求
- **响应时间**: API 响应时间 < 500ms（P95）
- **并发支持**: 支持至少 100 并发用户
- **数据库**: 
  - PostgreSQL 查询响应 < 100ms
  - MongoDB 查询响应 < 200ms
  - Redis 查询响应 < 10ms

### 3.2 安全需求
- **认证安全**:
  - 密码使用 bcrypt 加密（至少 10 轮）
  - JWT Token 使用 HS256 算法
  - Token 支持黑名单机制
- **数据安全**:
  - 防止 SQL 注入（参数化查询）
  - 防止 XSS 攻击（输入验证和输出转义）
  - 防止 CSRF 攻击（Token 验证）
  - 敏感信息加密存储
- **接口安全**:
  - 所有接口需要认证（除登录、注册）
  - 请求频率限制（未来功能）
  - IP 白名单（未来功能）

### 3.3 可用性需求
- **系统可用性**: 99.5%（月度）
- **数据备份**: 每日自动备份
- **故障恢复**: 支持快速恢复（< 1小时）

### 3.4 可扩展性需求
- **架构设计**: 模块化设计，便于拆分为微服务
- **数据库**: 支持水平扩展
- **缓存**: Redis 支持集群模式
- **API**: 支持版本控制（/api/v1/, /api/v2/）

### 3.5 兼容性需求
- **浏览器**: Chrome 90+, Firefox 88+, Safari 14+, Edge 90+
- **移动端**: 响应式设计，支持移动浏览器
- **API**: RESTful API，支持 JSON 格式

## 4. 技术约束

### 4.1 技术栈要求
- **后端**: Python 3.10+, FastAPI
- **前端**: React 18+, TypeScript（可选）
- **数据库**: PostgreSQL 15+, MongoDB 7+, Redis 7+
- **部署**: Docker, Docker Compose

### 4.2 开发规范
- **代码规范**: 
  - Python: PEP 8
  - JavaScript: ESLint + Prettier
- **API 规范**: RESTful API，遵循 OpenAPI 3.0
- **Git 规范**: Git Flow 工作流
- **文档规范**: Markdown 格式，API 文档使用 Swagger

## 6. 风险评估

### 6.1 技术风险
- **风险**: 数据库性能瓶颈
- **影响**: 高
- **应对**: 使用连接池、索引优化、缓存策略

### 6.2 安全风险
- **风险**: 数据泄露、XSS 攻击
- **影响**: 高
- **应对**: 严格输入验证、安全审计、定期安全测试

### 6.3 进度风险
- **风险**: 开发进度延期
- **影响**: 中
- **应对**: 敏捷开发、每日站会、及时调整计划
