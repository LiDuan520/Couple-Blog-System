## 2. 总体目标与原则

### 2.1 目标
按 PRD 完成 **MVP v1.0**：注册 / 登录 / 登出 / 资料管理 / 博客 CRUD / 列表分页 / 搜索标签筛选 / 基础安全。

### 2.2 原则
- **先修复基线，再叠功能**：第 4 章的缺陷修复在所有新功能开工前完成
- **接口先行**：每个模块先定 Schema + Endpoint，前后端并行
- **小步提交**：每个任务一个 PR，关联本文件对应 ID（如 `feat: M4-T01`）
- **可测优先**：每个模块至少 1 个冒烟测试，关键路径（auth/blog CRUD）有覆盖

### M3 · 后端 user 模块（1.0 人天）

**目标**：个人资料 / 头像 / 资料更新接口（PRD 第 2.1.4）。

**目录结构**（从零搭建）：
```
app/modules/user/
├── __init__.py
├── dependencies.py    # 复用 auth 依赖
├── schemas.py         # UserUpdate / AvatarUpload
├── service.py         # UserService
├── repository.py      # UserRepository（可与 auth 共享，初期直接调用 AuthRepository）
└── router.py          # /users 前缀
```

**API 约定**：

| Method | Path | 鉴权 | 描述 |
|---|---|---|---|
| GET | `/api/v1/users/me` | 是 | 当前用户资料（与 /auth/me 一致，作为 REST 风格别名） |
| PUT | `/api/v1/users/me` | 是 | 更新昵称/邮箱（用户名/密码不可改） |
| PUT | `/api/v1/users/me/password` | 是 | 修改密码（与 /auth/change-password 互通） |
| POST | `/api/v1/users/me/avatar` | 是 | 上传头像（multipart）→ 返回 URL |

**技术点**：
- 头像：MVP 阶段存本地 `backend/static/avatars/<user_id>.<ext>`，返回 `/static/avatars/xxx`
- 后续可替换为对象存储（任务留待 v1.1）

## 6. 接口契约（与后端 PRD/API 文档对齐）

最终交付的 REST 端点：

```
POST   /api/v1/auth/register
POST   /api/v1/auth/login
POST   /api/v1/auth/logout         (Auth)
POST   /api/v1/auth/refresh        (Auth)
POST   /api/v1/auth/change-password (Auth)

GET    /api/v1/users/me            (Auth)
PUT    /api/v1/users/me            (Auth)
PUT    /api/v1/users/me/password   (Auth)
POST   /api/v1/users/me/avatar     (Auth, multipart)

GET    /api/v1/blogs               (Auth)
POST   /api/v1/blogs               (Auth)
GET    /api/v1/blogs/{id}          (Auth)
PUT    /api/v1/blogs/{id}          (Auth)
DELETE /api/v1/blogs/{id}          (Auth)
GET    /api/v1/blogs/public        (Optional, Auth)

GET    /api/docs                   (Swagger UI)
GET    /api/redoc                  (ReDoc)
GET    /health                     (No Auth)
```

通用响应格式（成功）：
```json
{ "data": ..., "message": "ok" }
```

通用错误格式（已由 [ExceptionHandlerMiddleware](../backend/app/core/middleware.py) 实现）：
```json
{ "error": { "code": "VALIDATION_ERROR", "message": "..." } }
```

## 7. 风险与应对

| 风险 | 等级 | 应对 |
|---|---|---|
| Pydantic/SQLAlchemy 版本不匹配导致全员装包失败 | 🔴 高 | **先做 FIX-01/02/03**，CI 加 `pip install --dry-run` |
| `register` 不落库 / `logout` 无效 → 联调失败 | 🔴 高 | **先做 FIX-04/05**，写 e2e smoke |
| MongoDB 软删除索引选择不当 | 🟡 中 | 先不加 is_deleted 索引，监控后再优化 |
| 头像本地存储难扩 | 🟢 低 | MVP 接受，v1.1 切对象存储 |
| 限流误伤正常用户 | 🟡 中 | 阈值先宽松（login 10/min、write 60/min），观察日志再调 |
| 前端 Markdown 库体积 | 🟢 低 | 用 `react-markdown` + `remark-gfm`（≈80KB gzip） |
